## DOC-01: Core Runtime Architecture Specification

**Status:** Technical Architecture Specification  
**Version:** 1.0

**Parent Document:** [PingDart PRD](prd.md)  
**Target Phase:** Phase 1 (Desktop Proof-of-Concept)

# 1. Executive Summary

This document establishes the foundational runtime architecture of the **PingDart Framework**. The core runtime is responsible for:

1. Deterministic application lifecycle management.
2. A cross-platform, non-busy-waiting event loop.
3. Priority-based task scheduling (microtasks, macrotasks, timers, and background thread pool dispatch).
4. Predictable memory management and object ownership semantics.
5. Strict thread-safety and concurrency contracts.
6. A robust error handling strategy using value-based results.
7. A panic/exception-safe C-ABI FFI boundary for Rust (PingDartCore) integration.

```text
+--------------------------------------------------------------------------+
|                           Application Layer                              |
+--------------------------------------------------------------------------+
                                     |
+--------------------------------------------------------------------------+
|                            PingDart SDK                                  |
+--------------------------------------------------------------------------+
                                     |
+--------------------------------------------------------------------------+
|                       DOC-01: Core Runtime Engine                        |
|                                                                          |
|  +------------------+  +-------------------+  +-----------------------+  |
|  |    Event Loop    |  |  Task Scheduler   |  | Memory Arenas & Ref   |  |
|  | (epoll/MsgQueue) |  | (Timers/Workers)  |  | (Intrusive Smart Ptr) |  |
|  +------------------+  +-------------------+  +-----------------------+  |
|                                                                          |
|  +--------------------------------------------------------------------+  |
|  |                 Error System (`Result<T, Status>`)                 |  |
|  +--------------------------------------------------------------------+  |
|                                                                          |
|  +--------------------------------------------------------------------+  |
|  |               Rust FFI C-ABI Boundary (`extern "C"`)               |  |
|  +--------------------------------------------------------------------+  |
+--------------------------------------------------------------------------+
                                     |
+--------------------------------------------------------------------------+
|                  DOC-03: Platform Abstraction Layer (PAL)                 |
|                   (Win32, X11/Wayland, Cocoa, NDK, WASM)                 |
+--------------------------------------------------------------------------+
```

# 2. Threading & Concurrency Model

PingDart adopts a **disciplined multi-threaded architecture** designed to guarantee responsive 60/120 FPS UI execution while preventing race conditions, priority inversion, and UI freezes.

```text
[Platform / OS Events]
          |
          v
+-------------------+      Render Commands      +-------------------+
|     UI Thread     | ------------------------> |   Render Thread   | ----> [GPU Surface]
| (Main Event Loop) |   (Triple-buffered list)  |  (Vulkan / D3D12) |
+-------------------+                           +-------------------+
       ^     ^
       |     +-------------------------+
       v                               v
+-------------------+         +-------------------+
| Worker Pool (CPU) |         |  I/O Thread Pool  |
| (Image decoding,  |         | (Disk I/O, IPC,   |
|  Layout solver)   |         |  Network sockets) |
+-------------------+         +-------------------+
```

### 2.1 Thread Roles & Responsibilities

| Thread | Ownership | Responsibilities | Blocking Allowed? |
|---|---|---|---|
| **UI Thread (Main)** | Framework Runtime | Runs the primary event loop, dispatches OS input events, updates widget trees, executes layout calculations, and records paint display lists. | **STRICTLY PROHIBITED.** No synchronous disk I/O, network calls, or heavy CPU workloads. |
| **Render Thread** | GPU Subsystem | Consumes display lists generated by the UI thread, submits draw commands to the GPU (Vulkan/Metal/D3D12), and handles frame swaps. | Synchronized with display VSync. |
| **Worker Pool** | Task Scheduler | Thread pool (`std::thread::hardware_concurrency() - 1`) for compute-heavy tasks (image decoding, text shaping, compute tasks). | Non-blocking CPU computations. |
| **I/O Worker Pool** | I/O Subsystem | Dedicated asynchronous thread pool for disk file access, database queries, and network socket management. | Cooperative blocking allowed. |

### 2.2 Thread-Safety Contracts
1. **Thread Affiliation:** All `Widget`, `Element`, and `RenderObject` instances reside exclusively on the **UI Thread**. They are never accessed concurrently from background threads.
2. **Cross-Thread Communication:** Background threads communicate with the UI thread exclusively via asynchronous message queues processed by the UI thread's task scheduler.
3. **No Raw Locks on UI Thread:** The UI thread must never acquire a lock that can be held by an I/O thread or long-running worker. All synchronization uses lock-free single-producer single-consumer (SPSC) or multi-producer single-consumer (MPSC) queues.

# 3. Event Loop & Task Scheduler

The event loop provides deterministic, cooperative scheduling on the UI thread without spinning (zero CPU usage when idle).

### 3.1 Event Loop Phases

Each turn of the event loop executes through distinct sequential phases:

```text
1. Poll Platform Events (epoll / GetMessage with timeout)
         |
2. Process Microtask Queue (immediate callbacks, promises)
         |
3. Process Due Timers (delayed invocations)
         |
4. Process Asynchronous Macrotasks (worker results, network responses)
         |
5. Animation & VSync Frame Phase (layout, paint recording)
         |
6. Calculate Next Wakeup Timeout -> Sleep / Yield to OS
```

### 3.2 Platform Wake-up Mechanism
When background workers submit tasks to the UI thread while the UI thread is asleep in its platform wait function (`epoll_wait` on Linux, `MsgWaitForMultipleObjectsEx` on Windows):
- **Linux:** Writes a 64-bit counter to an `eventfd`.
- **Windows:** Calls `PostMessage(hwnd, WM_PINGDART_WAKEUP, ...)` or signals an auto-reset event handle.
- **macOS / iOS:** Signals a `CFRunLoopSource`.

# 4. Memory Ownership & Object Lifecycle

PingDart uses a hybrid memory management model designed to eliminate memory leaks, use-after-free bugs, and unpredictable garbage-collection pauses.

### 4.1 Ownership Semantics

| Object Category | Ownership Model | Justification |
|---|---|---|
| **Widgets** | Ephemeral, Immutable Value Objects | Created dynamically during build, lightweight, stack- or temporary-arena allocated. |
| **Elements & RenderObjects** | Hierarchical Tree Ownership | Managed by unique pointers (`std::unique_ptr`) down the tree; parents strictly own children. |
| **Shared Application Services** | Intrusive Reference Counting (`RefPtr<T>`) | Deterministic destruction; cache-friendly, zero separate control-block allocation overhead. |
| **Short-Lived Frame Allocations** | Frame Arena Allocator | Reset at the start of each frame; zero individual heap frees. |

### 4.2 Intrusive Reference Counting (`RefPtr<T>`)
Unlike `std::shared_ptr`, which requires an external control block allocation, PingDart's `RefPtr<T>` requires classes to inherit from `RefCounted<T>`:
- Eliminates secondary heap allocations.
- Enables safe conversion from `this` to `RefPtr<T>` without `enable_shared_from_this` overhead.
- Atomic reference counting enables safe cross-thread handoff.

# 5. Error Handling Contracts

PingDart enforces **explicit, value-based error handling** for all recoverable runtime conditions, reserving C++ exceptions strictly for unrecoverable fatal assertions.

### 5.1 Value-Based Results (`Result<T, Status>`)
Operations that can fail (file reading, network queries, parsing) return a `Result<T, Status>` type (modeled after `std::expected`):

```cpp
template <typename T, typename E = Status>
class Result;
```

### 5.2 Status Model
`Status` encapsulates:
- `StatusCode` (e.g., `Ok`, `NotFound`, `PermissionDenied`, `Timeout`, `InternalError`).
- A lightweight error message string.
- Platform error code (e.g., Win32 `GetLastError()` or POSIX `errno`).

### 5.3 Exception Policy
- Engine internal code avoids throwing C++ exceptions across module boundaries.
- Fatal programming errors (e.g., null dereference assertions, out-of-bounds contract violations) invoke `PINGDART_PANIC(...)`, which prints a stack trace and cleanly halts the process.

# 6. Rust ↔ C++ FFI Boundary Specification

PingDart integrates with the Rust-based PingDartCore compiler and language subsystems via an unambiguous C-ABI boundary.

```text
+-----------------------------------------------------------+
|               C++ Framework Runtime Engine                |
|                      (C++20 Classes)                      |
+-----------------------------------------------------------+
                             |
                   C++ Wrapper / RAII Guard
                             |
+-----------------------------------------------------------+
|          STRICT C-ABI BOUNDARY (`extern "C"`)             |
|                                                           |
|  - Opaque Pointers: `pd_context_t*`, `pd_ast_t*`         |
|  - Fixed-width types: `int32_t`, `uint64_t`, `const char*`|
|  - Integer status returns: `pd_status_t`                  |
|  - Zero unwinding: Rust `catch_unwind`, C++ `try/catch`   |
+-----------------------------------------------------------+
                             |
                     Rust FFI Bindings
                             |
+-----------------------------------------------------------+
|            PingDartCore Compiler Subsystem                |
|                        (Rust)                             |
+-----------------------------------------------------------+
```

### 6.1 FFI Invariants & Safety Rules
1. **Opaque Handles:** Rust structs are never passed by value. They are exposed as opaque pointers (`typedef struct pd_context_t pd_context_t;`).
2. **Explicit Allocator Symmetry:**
   - Any buffer or struct allocated by Rust must be deallocated using a matching Rust FFI export (e.g., `pd_free_buffer()`).
   - C++ `free()` or `delete` must never be called on Rust memory, and vice-versa.
3. **Panic and Exception Containment:**
   - Every Rust FFI function must be enclosed in `std::panic::catch_unwind`. If a panic occurs, it is captured and converted to `PD_STATUS_INTERNAL_PANIC`.
   - C++ callers must never allow exceptions to unwind into Rust stack frames.
4. **Binary Compatibility:**
   - All FFI structs use `#pragma pack(push, 8)` / `#[repr(C)]`.
   - String parameters are null-terminated UTF-8 with explicit length (`const char* str, size_t len`).

# 7. C++20 Core Interfaces

Below are the canonical C++20 header definitions for the foundational runtime primitives.

### 7.1 Status & Result (`pingdart/core/result.h`)

```cpp
#pragma once
#include <string>
#include <string_view>
#include <variant>
#include <utility>

namespace pingdart::core {

enum class StatusCode : int32_t {
    Ok = 0,
    InvalidArgument = 1,
    NotFound = 2,
    AlreadyExists = 3,
    PermissionDenied = 4,
    ResourceExhausted = 5,
    FailedPrecondition = 6,
    Aborted = 7,
    OutOfRange = 8,
    Unimplemented = 9,
    Internal = 10,
    Unavailable = 11,
    Timeout = 12
};

class [[nodiscard]] Status {
public:
    Status() : code_(StatusCode::Ok) {}
    Status(StatusCode code, std::string message, int32_t platform_error = 0)
        : code_(code), message_(std::move(message)), platform_error_(platform_error) {}

    [[nodiscard]] bool ok() const noexcept { return code_ == StatusCode::Ok; }
    [[nodiscard]] StatusCode code() const noexcept { return code_; }
    [[nodiscard]] std::string_view message() const noexcept { return message_; }
    [[nodiscard]] int32_t platform_error() const noexcept { return platform_error_; }

    static Status Ok() { return Status(); }

private:
    StatusCode code_;
    std::string message_;
    int32_t platform_error_ = 0;
};

template <typename T>
class [[nodiscard]] Result {
public:
    Result(T value) : data_(std::move(value)) {}
    Result(Status status) : data_(std::move(status)) {}

    [[nodiscard]] bool has_value() const noexcept {
        return std::holds_alternative<T>(data_);
    }

    [[nodiscard]] const T& value() const {
        return std::get<T>(data_);
    }

    [[nodiscard]] T& value() {
        return std::get<T>(data_);
    }

    [[nodiscard]] const Status& status() const {
        if (has_value()) {
            static const Status s_ok = Status::Ok();
            return s_ok;
        }
        return std::get<Status>(data_);
    }

private:
    std::variant<T, Status> data_;
};

} // namespace pingdart::core
```

### 7.2 Intrusive Reference Counting (`pingdart/core/ref_ptr.h`)

```cpp
#pragma once
#include <atomic>
#include <utility>

namespace pingdart::core {

template <typename T>
class RefCounted {
public:
    void add_ref() const noexcept {
        ref_count_.fetch_add(1, std::memory_order_relaxed);
    }

    void release() const noexcept {
        if (ref_count_.fetch_sub(1, std::memory_order_acq_rel) == 1) {
            delete static_cast<const T*>(this);
        }
    }

    [[nodiscard]] uint32_t ref_count() const noexcept {
        return ref_count_.load(std::memory_order_relaxed);
    }

protected:
    RefCounted() = default;
    virtual ~RefCounted() = default;

private:
    mutable std::atomic<uint32_t> ref_count_{0};
};

template <typename T>
class RefPtr {
public:
    RefPtr() noexcept : ptr_(nullptr) {}
    RefPtr(std::nullptr_t) noexcept : ptr_(nullptr) {}

    explicit RefPtr(T* ptr) noexcept : ptr_(ptr) {
        if (ptr_) ptr_->add_ref();
    }

    RefPtr(const RefPtr& other) noexcept : ptr_(other.ptr_) {
        if (ptr_) ptr_->add_ref();
    }

    RefPtr(RefPtr&& other) noexcept : ptr_(other.ptr_) {
        other.ptr_ = nullptr;
    }

    ~RefPtr() {
        if (ptr_) ptr_->release();
    }

    RefPtr& operator=(const RefPtr& other) noexcept {
        if (this != &other) {
            if (other.ptr_) other.ptr_->add_ref();
            if (ptr_) ptr_->release();
            ptr_ = other.ptr_;
        }
        return *this;
    }

    RefPtr& operator=(RefPtr&& other) noexcept {
        if (this != &other) {
            if (ptr_) ptr_->release();
            ptr_ = other.ptr_;
            other.ptr_ = nullptr;
        }
        return *this;
    }

    [[nodiscard]] T* get() const noexcept { return ptr_; }
    [[nodiscard]] T* operator->() const noexcept { return ptr_; }
    [[nodiscard]] T& operator*() const noexcept { return *ptr_; }
    [[nodiscard]] explicit operator bool() const noexcept { return ptr_ != nullptr; }

    void reset(T* ptr = nullptr) noexcept {
        if (ptr) ptr->add_ref();
        if (ptr_) ptr_->release();
        ptr_ = ptr;
    }

private:
    T* ptr_;
};

template <typename T, typename... Args>
RefPtr<T> make_ref(Args&&... args) {
    return RefPtr<T>(new T(std::forward<Args>(args)...));
}

} // namespace pingdart::core
```

### 7.3 Task Scheduler & Event Loop (`pingdart/core/event_loop.h`)

```cpp
#pragma once
#include "result.h"
#include <chrono>
#include <functional>
#include <memory>
#include <vector>

namespace pingdart::core {

using Task = std::function<void()>;
using Clock = std::chrono::steady_clock;
using TimePoint = Clock::time_point;
using Milliseconds = std::chrono::milliseconds;

class EventLoop {
public:
    virtual ~EventLoop() = default;

    // Dispatches a task to execute on the next turn of the loop
    virtual void post_task(Task task) = 0;

    // Schedules a task to execute after a specified delay
    virtual void post_delayed_task(Task task, Milliseconds delay) = 0;

    // Schedules high-priority microtask
    virtual void post_microtask(Task task) = 0;

    // Runs a single turn of the event loop with an optional maximum wait timeout
    virtual bool run_one(Milliseconds timeout) = 0;

    // Runs the loop until terminate() is called
    virtual int run() = 0;

    // Signals the event loop to stop processing and exit run()
    virtual void terminate(int exit_code = 0) = 0;

    // Returns whether current execution thread is the loop's owning UI thread
    [[nodiscard]] virtual bool is_on_loop_thread() const noexcept = 0;

    // Creates the platform-appropriate event loop instance
    static std::unique_ptr<EventLoop> create();
};

} // namespace pingdart::core
```

# 8. Minimal Compilable Runtime Skeleton

Below is a self-contained, working C++20 proof-of-concept skeleton implementing the core event loop, thread-safe task posting, timers, and clean shutdown.

```cpp
// pingdart_runtime_skeleton.cpp
// Build with: clang++ -std=c++20 -O2 pingdart_runtime_skeleton.cpp -o pd_skeleton -lpthread

#include <iostream>
#include <chrono>
#include <functional>
#include <queue>
#include <mutex>
#include <condition_variable>
#include <thread>
#include <atomic>
#include <vector>

namespace pd {

using Task = std::function<void()>;
using Clock = std::chrono::steady_clock;
using TimePoint = Clock::time_point;
using Milliseconds = std::chrono::milliseconds;

struct DelayedTask {
    TimePoint due_time;
    uint64_t sequence;
    Task task;

    bool operator>(const DelayedTask& other) const {
        if (due_time == other.due_time) {
            return sequence > other.sequence;
        }
        return due_time > other.due_time;
    }
};

class CoreEventLoop {
public:
    CoreEventLoop() : ui_thread_id_(std::this_thread::get_id()), running_(false), exit_code_(0), task_seq_(0) {}

    void post_task(Task task) {
        {
            std::lock_guard<std::mutex> lock(mutex_);
            ready_tasks_.push(std::move(task));
        }
        cv_.notify_one();
    }

    void post_delayed_task(Task task, Milliseconds delay) {
        TimePoint due = Clock::now() + delay;
        {
            std::lock_guard<std::mutex> lock(mutex_);
            delayed_tasks_.push({due, ++task_seq_, std::move(task)});
        }
        cv_.notify_one();
    }

    int run() {
        running_ = true;
        std::cout << "[Runtime] EventLoop started on thread " << ui_thread_id_ << std::endl;

        while (running_) {
            std::vector<Task> tasks_to_run;

            {
                std::unique_lock<std::mutex> lock(mutex_);

                if (ready_tasks_.empty() && delayed_tasks_.empty()) {
                    cv_.wait(lock, [this] { return !running_ || !ready_tasks_.empty() || !delayed_tasks_.empty(); });
                } else if (ready_tasks_.empty() && !delayed_tasks_.empty()) {
                    auto next_due = delayed_tasks_.top().due_time;
                    cv_.wait_until(lock, next_due, [this, next_due] {
                        return !running_ || !ready_tasks_.empty() || Clock::now() >= next_due;
                    });
                }

                if (!running_) break;

                // Move due delayed tasks into ready queue
                auto now = Clock::now();
                while (!delayed_tasks_.empty() && delayed_tasks_.top().due_time <= now) {
                    ready_tasks_.push(delayed_tasks_.top().task);
                    delayed_tasks_.pop();
                }

                // Batch extract ready tasks
                while (!ready_tasks_.empty()) {
                    tasks_to_run.push_back(std::move(ready_tasks_.front()));
                    ready_tasks_.pop();
                }
            }

            // Execute tasks outside of lock
            for (auto& task : tasks_to_run) {
                if (task) task();
            }
        }

        std::cout << "[Runtime] EventLoop stopped with exit code " << exit_code_ << std::endl;
        return exit_code_;
    }

    void terminate(int exit_code = 0) {
        {
            std::lock_guard<std::mutex> lock(mutex_);
            running_ = false;
            exit_code_ = exit_code;
        }
        cv_.notify_all();
    }

    bool is_on_loop_thread() const noexcept {
        return std::this_thread::get_id() == ui_thread_id_;
    }

private:
    std::thread::id ui_thread_id_;
    std::atomic<bool> running_;
    int exit_code_;
    uint64_t task_seq_;

    std::mutex mutex_;
    std::condition_variable cv_;
    std::queue<Task> ready_tasks_;
    std::priority_queue<DelayedTask, std::vector<DelayedTask>, std::greater<DelayedTask>> delayed_tasks_;
};

} // namespace pd

// Demonstration of the Core Runtime
int main() {
    pd::CoreEventLoop loop;

    // 1. Post initial task
    loop.post_task([&]() {
        std::cout << "[App] App initialized on UI Thread." << std::endl;
    });

    // 2. Post delayed task (timer)
    loop.post_delayed_task([&]() {
        std::cout << "[App] Timer fired after 500ms!" << std::endl;
    }, pd::Milliseconds(500));

    // 3. Dispatch task from a background worker thread
    std::thread worker([&loop]() {
        std::this_thread::sleep_for(std::chrono::milliseconds(250));
        std::cout << "[Worker] Background work completed. Posting result to UI thread..." << std::endl;
        loop.post_task([&loop]() {
            std::cout << "[App] Received background worker result on UI thread!" << std::endl;
        });
    });

    // 4. Clean termination timer
    loop.post_delayed_task([&]() {
        std::cout << "[App] Initiating clean shutdown..." << std::endl;
        loop.terminate(0);
    }, pd::Milliseconds(800));

    int result = loop.run();
    worker.join();
    return result;
}
```
